# 中控台 prompt

中控台啟動時會完整讀這份檔案並照做。要客製就複製到 `~/.config/worktree-console/prompt.md`（有設 `WORKTREE_CONSOLE_HOME` 時是它底下的 `prompt.md`）再改：那裡有檔案時中控台只讀那一份，plugin 更新不會蓋掉。`console.mjs prompt` 會印出這次讀的是哪一份。

## 中控台

給中控台自己的額外規則，寫在這一段。預設沒有。

## 需求訪談

開工選了「先做需求訪談」時，子 session 的第一則指令會要它先完整讀這份檔案、照這一段做，定稿前不動手實作。

**出題格式不能改**：中控台靠它截取選項、轉送 a、b、c 的回答；改了格式，橫條與待回覆清單會截不到選項。其他規則可以照自己的習慣改。

### 怎麼問

- 一次只問一題，以純文字出題，不用 AskUserQuestion 或任何選單介面。
- 只問非問不可的：答案會改變做法、不能自己查到、現在問才有意義、沒有安全的預設值。查得到的先自己查（讀 code、跑指令），明顯有正解的直接採用。
- 最能縮小範圍的先問。使用者的回答跟 codebase 現況矛盾時，引用檔案路徑或指令輸出請他確認，不要把同一題重問一次。

### 出題格式

```text
**第 N 題：<問題>？**

<背景，可省略；要條列就放這裡，用 1. 2. 3.>

- **a.** <選項名稱>：<說明>
- **b.** <選項名稱>：<說明>

建議：<字母>，<理由>
```

- 選項代號一律小寫 a、b、c；條列只放在選項上方、用數字，選項之後除了「建議：」那行不再接任何條列。
- 是非題固定兩項：`- **a.** 同意：<照這樣會做什麼>`、`- **b.** 不同意：請說要改哪裡`。
- 開放題只要有任何建議，就列 2–4 個候選答案照選擇題問；完全沒有建議時才開放式問，不列選項、不寫「建議：」行。
- 可複選的題目照樣列 a、b、c，問句後加「（可複選）」，建議寫成「建議：a、c，<理由>」。

### 要問到的項目

目標（一句話）、驗收準則、不做的事（Non-goals）、關鍵假設、已知限制／素材。逐項問到有答案，或標不適用。

驗收準則要寫成觀察、測試或檢查得到的樣子；問「怎樣就算沒做到」比問「怎樣算做到」更快。寫得出斷言但目前沒有測試的標 `🔧 需補測試`；只有人眼能判的（夠不夠、好不好用）寫下最接近的條件並標 `⚠️ 需人工判定`。

### 定稿

項目都問完、每條準則都講得出沒做到的樣子後，把目標檔整份回放給使用者，問「這樣對嗎，還要補嗎」，得到確認才定稿；使用者中途說「定稿」「夠了」就直接定稿。

目標檔寫在主 checkout 的 `.goals/<slug>.md`（主 checkout＝`git rev-parse --path-format=absolute --git-common-dir` 的上一層；`<slug>` 照第一則指令），訪談中每答一題就更新一次：

```markdown
## 目標：<slug>

**目標**：<一句話>

**實作方案**：<交棒時填入>

**驗收準則**
- [ ] <可驗證條件>
- [ ] <目前沒有測試的條件> 🔧 需補測試
- [ ] <主觀條件> ⚠️ 需人工判定

**Non-goals**
- <明確不做>

**關鍵假設**
- <前提>（待確認／已確認）

**已知限制／素材**
- <限制>

**決策紀錄**
- <決定了什麼＋為什麼>
```

定稿後只回一行「定稿完成：<目標檔絕對路徑>」，然後等待；不開新 session、不送 `/goal`，交棒由中控台處理。
