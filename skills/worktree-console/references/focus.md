# 專注模式（有 mods 時）

- mods 有兩個，都只在支援 mods 的 Claude Code、且是中控台自己的分頁才作用；同一個分頁裡沒載入過本 skill 的 Claude session（例如背景常駐程式預先開好的備用 session）不畫橫條、不印題目：
  - 本 plugin 的 `hooks/worktree-console-focus.tsx`：輸入框上方的橫條與側邊面板；輸入框下方的提示行不加任何字，照 Claude Code 原樣。它每 5 秒輪詢 `console.mjs focus`，這個輪詢就是「有 mods」的訊號，watcher、`after-send` 據此切換。
  - 獨立的 `focus-show` plugin（本 repo 的 `mods/focus-show/`，marketplace 另列一項，要另外安裝）：提供 `/focus-show <代號>`，把該題完整回報（與 watcher 回報同格式）直接畫在對話，不經模型、不耗 token。一定要獨立：mod 用 `$.command.run` 發的指令不會交給同一個 mod 自己的 `command.run`。
  - 兩者共用的 `focus.json` 欄位、`show/` 檔名、題目編號與版本號規則見 [focus-contract.md](focus-contract.md)。
- 面板與橫條只有一種畫法；`config.json` 的 `theme`、`motion`、`autoShow` 怎麼設見 README〈外觀〉。`autoShow` 設成 `false` 時，題目換上橫條不自動用 `/focus-show` 印出，按 `9` 或摘要浮層的 `d`→`p` 照舊能印。橫條：第一行 `── 待回覆 <目前這題 1 或 0>/<總題數> ───` 分隔線；第二行是標題列：左邊狀態圖示＋狀態字（工作中、待回答、待授權、已回覆、閒置、異常）＋粗體暱稱（純文字、不可點、不可聚焦），右邊用主題的淡色寫 `9: 顯示問題`，排隊列有題時前面加 `8: 延後處理 · `（變成 `8: 延後處理 · 9: 顯示問題`），右端貼齊橫條寬度；窄到放不下時先把暱稱以「…」截短，兩個按鈕一律完整、不折行；接著完整題目（放不下以「…」截短；需求訪談的批改單——最後一個「第 N 題」標題含「批改單」——改寫 `批改單 待決定 N 題（🔴 M 題要你看）`，N 是單上 `**待決定 N：…？**` 題目行的數目（`**已決定**` 底下的編號行不算）、M 是其中標 🔴 的；舊格式沒有待決定時照舊寫 `批改單 N 題（🔴 M 題要你看）`，N 是單上 1. 2. 3. 的題數；選項只截最後一組全照建議的 a、b、c；整張單按 9 用 `/focus-show` 印），按鈕不另佔一行；題目下方一行是 agent-skills advisor 的建議（`console.mjs focus` 讀 `~/.advisor/predictions.jsonl`，子 session 停下時由 advisor 的 Stop hook 在背景產生）：預測還沒好寫 `建議產生中… N 秒`（淡色，秒數每次輪詢更新），好了在下一次輪詢換成 `建議：<答案>，<一句理由>`（`建議：` 用主題強調色、答案粗體；答案是 a、b、c 時後面接該選項冒號前的字；理由用次要色），不可逆或沒有前例的題目接 `（原則性：<類別>）`（用「待回答」的狀態色；舊預測標的範圍與目標、產品行為不再註明）；放不下時先以「…」截短理由、再拿掉選項字，答案與原則性註記一律留著；預測失敗、🔐 等你授權、⏸ 回覆完畢、沒裝 advisor（沒有 `~/.advisor/`）都不顯示這一行，`/focus-show` 的回報也不放建議；最後一行 `其他 1: <暱稱>[ ✨] · 2: … · ＋N · 0: 面板`，排隊列最多顯示 5 個（不足 60 欄時只顯示 1 個，其餘併進 `＋N`，數字鍵照樣有效），不顯示「另有 N 題」（總數看面板 `待回覆` 分頁標題）。各行左側一條直線，顏色跟著目前這題的狀態色。輸入框空白時：1–5 切到那題（6、7 不是橫條鍵，照常打進輸入框；第 6 題以後開面板按數字；原題沒回就切走算跳過，規則見下方〈排隊〉）、8 把目前這題移到排隊列最後、換排隊列第一題上橫條並印出、9 再印一次目前這題、0 開面板並取得鍵盤（面板只從 `0` 開）。
- 面板分頁 `待回覆`(q)／`全部`(w)／`封存`(e)，內容是卡片。`全部` 列出所有沒封存的 session，閒置的也在裡面（卡片照樣標「閒置」），封存的只在 `封存`。`待回覆` 永遠跟橫條同步：第一張是橫條目前這題（不給數字）、其後照排隊順序標 1、2…（前 5 張與橫條同一 session 同一數字，第 6 張以後繼續標 6、7…、第 10 張是 0），面板開著時也即時重排；其他分頁依 repo 分組，數字照位置給 1–9、0。分頁列是 `q: 待回覆 N`、`w: 全部 N`、`e: 封存 N`，平均分散排滿整行：第一個分頁貼左、最後一個貼右，多出的空白平均分在分頁之間；下一行是整條細線、所選分頁正下方換成粗線 `━`，寬度等於該分頁標籤；不足 46 欄時沒選的分頁只留按鍵與數字，整行仍是一列。上／下在卡片間移動選取（兩端停住，移到畫面外的卡片會自動捲到完整可見）；左／右在面板裡引擎沒有綁鍵，切分頁用 q/w/e。按鍵說明 `qwe 切分頁 · 1-9,0/↑↓ 選卡片` 緊接在最後一張卡片（沒有卡片時是空白框）下面、中間空一行，補滿整行、文字置中，前後用灰色 `─` 夾住（兩邊至少各 2 個，太窄時先以「…」截說明文字），卡片少時下方留白；面板裡沒有統計。卡片多到要捲動時由 mod 自己管捲動（滾輪一張、翻頁鍵一整頁），按鍵說明跟著捲：沒捲到底時可見區域全部給卡片，捲到底時最後一張卡與按鍵說明都完整露出。數字鍵只負責選卡片：在 `待回覆` 選卡片＝切題（換人時照樣自動印出），其他分頁只瀏覽（除非那張也在待回覆中）；上下鍵只選卡、不切題。選中卡片按 Enter（焦點一律落在選取卡片的暱稱上）或點卡片上的暱稱，等於按那張卡的數字鍵：卡片在等回答時橫條換成這張卡的問題，沒在等回答時只選中它。按 `d` 在選中卡片正下方打開或收起摘要浮層（見下方〈浮層〉），浮層裡按 `p` 印出完整回報。卡片不畫外框：每張固定兩行，卡片上方空一行，一張佔 3 列；左側不畫直線，狀態色只上在狀態圖示；最左一格空白，接著兩格留給選中標記：選中的卡在這裡放強調色、粗體的 `✻`，其他卡留空，第二行也一起往右；三個分頁的卡片都一樣，repo 的分組標題線照舊貼左。面板拿到鍵盤且 `motion` 開著時，標記照 Claude Code 的轉圈字元 `· ✢ ✳ ✶ ✻ ✽` 來回轉（每 150ms 換一格）；鍵盤交回輸入框或 `motion: false` 時停在 `✻`，不為它開計時器。標題列是數字鍵、狀態圖示＋狀態字、暱稱（粗體、前景色；選中的用強調色），暱稱後面隔 2 格接題目（灰字，多行題目併成一行，放不下以「…」截短、不換行），不放階段；有待審代回的卡狀態字寫 `◈ 待審核`（待回答的狀態色），標題列右端貼齊寫 `需審核 N 件`；建議好了的卡右端寫 `✓ 建議`（✓ 強調色）。代號太長時先把代號以「…」截短、題目至少留 8 格，標題列永遠一行。第二行在數字欄下方縮排，左邊是 branch（主題淡色）、右邊是 repo（主題淡色再加暗淡，右端貼齊卡片右緣），中間至少隔 2 格；放不下時 repo 至少留 8 格、branch 以「…」截短。卡片上不顯示選項（完整選項看橫條與印出的回報），也不顯示建議內容；面板裡任何地方（卡片、摘要浮層、審核單）都不顯示階段。`待回覆` 的卡片文字中只有暱稱是前景色粗體（選中時強調色粗體），狀態圖示與狀態字照原本的狀態色，題目、branch、repo 都是灰字，`✓ 建議` 的 ✓ 照舊用強調色。卡片高度固定，捲動照每張 3 列計算；其他分頁的 repo 分組線上方空一行，與它下面第一張卡之間也空一行（就是每張卡上方那一行），捲動時一條分組線多算 2 列。卡片不放票名。「封存」分頁的卡片把暱稱按鈕換成「取消封存」：mod 直接跑 `console.mjs unarchive <代號>`，不經中控台、對話不留結果行，卡片照狀態回到其他分頁與看板。
- 面板開啟時要求 Claude Code 不畫面板本身的底色（`backgroundColor: "transparent"`），`neutral` 主題的面板背景就是終端機本身的背景；命名主題照舊畫自己的底色。
- 浮層：摘要畫在面板裡、不另開面板。浮層從選中卡片的正下方展開，蓋在下面的卡片上、不推動它們；卡片在面板下半部時改畫在卡片上方，但不蓋到分頁列。最上面一條強調色分隔線寫標題（`<代號> 摘要`），內容每行左側一條強調色粗線 `┃`，長內容照寬度換行、不截斷，最下面一條分隔線；摘要浮層在分隔線下面再一行灰字 `d 收起 · p 印出完整回報`。高度最多到面板可見範圍的邊緣；內容放不下時用滾輪、翻頁鍵或 `j`／`k` 捲動浮層內容，底線寫 `j/k 捲動 · 第 N–M 行／共 T 行`。浮層開著時滾輪與翻頁鍵只捲浮層、不捲卡片。再按一次 `d`、↑↓ 換到別張卡、切分頁、或按 Esc 把鍵盤交回輸入框，浮層就收起；同時只會有一個浮層。摘要浮層：直接從該 session 最新的摘要開始，不寫 repo、階段與票名。四層摘要一層一段：標籤（`在做什麼`、`卡在哪`、`做了什麼`、`▶ 要你決定`、`下一步`）是固定左欄、灰字，內容前景色，換行時對齊內容欄；`▶ 要你決定` 前空一行、整行強調色粗體；`下一步` 不加 ▶、照一般字色。舊摘要檔的舊標籤（前提、問題、解法、建議）照新標籤畫；沒有標籤的摘要照原文換行。沒有摘要時灰字寫 `還沒有摘要`，產生中灰字寫 `摘要產生中…`，舊摘要下方有新的在產生時多一行灰字 `新的摘要產生中…`。`p` 收起浮層後印出完整回報：經 `/focus-show` 印在中控台對話、不經模型，待回覆中且不在橫條上的卡先切上橫條（切題時照樣自動印出）。`封存` 分頁的暱稱位置是取消封存按鈕，沒有摘要浮層。
- 只有緊急題上橫條：🔐 等待授權與 ⚠️ session 異常一停下就上；其他題先等 agent-skills advisor 在背景判完（預測的 `urgent` 欄），判成緊急才上橫條，判成非緊急就由中控台直接代回、不上橫條也不進待回覆；停下超過 2 分鐘還判不出來（還在判、預測失敗、舊版 advisor 沒判緊急）算緊急。緊急名單 10 類：等待授權、session 異常、不可逆或對外動作（push、合併、刪資料或 branch、寫 Linear／Slack、改遠端設定）、代價高的決定（方向、範圍、資料寫入、權限）、需使用者本人判定的驗收與原型確認、加進〈不做〉或拿掉先前決定、要用秘密值、要連 SSH 或 RDS、連續 3 個假設失敗、判斷不出是否緊急；一則訊息只要有一題緊急，整則算緊急。沒有選項的開放題照同一套規則代回；一般句子的問句要在最後一段、不在程式碼、引用框、表格或標題裡才算在問，沒有問號的回覆不算。下面幾種也照常上橫條、不代回：問號不在最後一段的回覆、dev-flow 未定題（`第 N 題（gate#…）`，算第 5 類）、子 session 被攔截點擋下而停下的那則、define-goal 與前端精簡路徑的批改單（那張單就是這張票的實作前審核）、⏸ 回覆完畢。沒裝 advisor 時一律照舊上橫條。
- 代回（watcher 每一輪做）：非緊急題先用 `console.mjs review add` 的同一套格式記成審核項目（一則多題拆成多件，advisor 給每題一句題目、當前方案、影響範圍；有前例時寫出處），再用 advisor 的 `auto` 記成代回，最後用 `console.mjs reply --only <代號> -- <答案>` 送出（`--only` 只送這個代號，找不到就失敗，不退回送給橫條那題）。不倒數、不看題型猜中率。送失敗時替那幾件補一行「未送出」、用 advisor 的 `undo` 撤回，題目改上橫條。中控台輸入框有字時（mod 每次輪詢帶 `--typing 1`）這一輪不代回。前端完整路徑（第一則回覆寫「走完整」或 run folder 有 goal.md 且不是 `path: lean`）的批改單沒有 🔴 時代回「（中控台代回，待實作前審核）全照建議」，單上每個待決定各成一件審核項目、當前方案是它的建議；任何批改單有 🔴 都算緊急。前端 implement 停在「檢查完回「送審」」時，讀 run folder 的 `implement-report.md`：〈卡點與待裁決〉是「無」、沒有需人工判定的準則、那則也沒帶別的題目才自動送「送審」，否則照常上待回覆。
- 代回中：中控台代回後、子 session 還在跑這一輪時（`delegated.json` 裡這個 session 最近一筆代回，且這一輪的開始時間落在送出後 2 分鐘內），卡片狀態寫 `↻ 代回中`（已回覆色），第二行左邊改寫 `已代回：<答案>`；看板的狀態圖示換成 ↻、下一行寫 `代回中 · 已代回：<答案>`。它下次停下就恢復；`需審核 N 件` 照舊。
- 審核單：有待審代回的卡片狀態字寫 `待審核`、標題列右端寫 `需審核 N 件`。選中這張卡按 Enter（或點暱稱）在面板裡打開這個 worktree 的審核單（`console.mjs review data --json`），其他卡片暫時收起：第一行 `審核單：<代號>`，第二行左邊 branch（有 PR／MR 時接 ` · PR #N`）、右邊 repo；只分「先看：沒有前例」（每件四行：題目、當前方案、依據、影響範圍）與「照你過去的回答」（每件兩行：題目、當前方案＋出處）兩區，沒有開頭說明句；「當前方案」「依據」「影響範圍」等欄位名用主題最淡的灰；待審那件的題目用粗體，色碼主題用強調色混 60% 進前景色，neutral 維持前景色。↑↓ 選件；Enter 通過一件（縮成一行打勾、游標跳到下一件）；`e` 在那件下面就地打字改（標「已改」）；`x` 在那件下面就地問：空白直接按 Enter＝要一個實際範例，打字＝問任何問題，回答插在那件下面（`問`／`答`，範例標 `範例`），問很多輪時只展開最新一輪、前面幾輪收成一行，按 `h` 展開；`c` 把那件印到中控台對話討論；`o` 打開那件的範例檔；`a` 通過「照你過去的回答」那區剩下的件（「先看：沒有前例」那區不給 `a`，要一件一件按）；Esc 回卡片，進度存在紀錄裡。整張審完自動跑 `console.mjs review done`。
- 範例（`x` 空白 Enter，或 `console.mjs review ask --n N`）：前端畫面附子 session 記下的實際本機 dev server 改前改後截圖（`review add --before/--after`），截不到時附原型截圖並標「這是原型」（`--prototype`）；複雜邏輯附 mermaid 流程圖；簡單行為寫一個「如果…，會…」情境。範例檔放在審核紀錄旁的 `examples/`，按 `o` 打開。
