# 專注模式（有 mods 時）

- mods 有兩個，都只在支援 mods 的 Claude Code、且是中控台自己的分頁才作用；同一個分頁裡沒載入過本 skill 的 Claude session（例如背景常駐程式預先開好的備用 session）不畫橫條、不印題目：
  - 本 plugin 的 `hooks/worktree-console-focus.tsx`：輸入框上方的橫條與側邊面板；輸入框下方的提示行不加任何字，照 Claude Code 原樣。它每 5 秒輪詢 `console.mjs focus`，這個輪詢就是「有 mods」的訊號，watcher、`after-send` 據此切換。
  - 獨立的 `focus-show` plugin（本 repo 的 `mods/focus-show/`，marketplace 另列一項，要另外安裝）：提供 `/focus-show <代號>`，把該題完整回報（與 watcher 回報同格式）直接畫在對話，不經模型、不耗 token。一定要獨立：mod 用 `$.command.run` 發的指令不會交給同一個 mod 自己的 `command.run`。
  - 兩者共用的 `focus.json` 欄位、`show/` 檔名、題目編號與版本號規則見 [focus-contract.md](focus-contract.md)。
- 面板與狀態區只有一種畫法；`config.json` 的 `theme`、`motion` 怎麼設見 README〈外觀〉。狀態區（輸入框上方）的字全由 `console.mjs focus` 組好，mod 只照它給的每一段文字與顏色畫，不自己組字：第一行 `── 狀態 ───` 分隔線；之後每行左側一條直線（目前這件的狀態色，等它回應時是淡色）。
  - 有目前這件時第一行是 `◆ <狀態> <代號>`（輪到你黃、等待授權洋紅、session 異常紅；狀態字粗體、代號粗體），右端貼齊寫按鍵 `8 延後處理   9 顯示問題   0 面板`（數字粗體、說明暗色、鍵與鍵之間三格；沒有別題在等時沒有 8；窄到放不下時只留數字）；下一行是建議：中控台跑過 `guide --mine` 時是 `中控台建議  <建議>  <理由>`，advisor 的建議退成下一行暗字 `advisor 建議  <答案>  <理由>`；沒有中控台建議時是 `建議  <答案>  <理由>`（`建議` 強調色、答案粗體、理由暗色；答案是 a、b、c 時接該選項冒號前的字；原則性題目接 `（原則性：<類別>）`）；advisor 還在產生時寫 `建議產生中… N 秒`；已完成但還沒推時寫 `建議  回 <代號>「送出」  它說已完成，但還有 N 個 commit 沒推，送出會開 draft MR`。帶 `--self` 時多一行 `要你回  <題號>     照建議  <題號>`（要你回的題號粗體黃，連續三題以上寫成「1～3」）。剛回完一件、換到下一件時多一行 `剛送出  <代號>：<內容>     它回來後排在下一件`。
  - 等某個 session 回應時第一行是 `◌ 等 <代號> 回應中…　你回了 <內容>`（代號粗體），右端 `8 先處理下一件   0 面板`（有別題在等才有 8）。
  - 接著是分組那行，和 `console.mjs waiting-line` 同一份分組，依序畫 `等待`、`自動處理中`、`在跑`、`延後處理`、`可關閉`：組名不粗體、各用一色（等待黃、自動處理中亮青、在跑綠、延後處理灰、可關閉亮藍），組與組之間五格空白，沒有代號的組整組不畫；等待與可關閉的代號用組色粗體，其他組的代號用一般字色。一行放不下時依序把延後處理、在跑、自動處理中、可關閉縮成「組名 數字」，都縮了還放不下才把等待最後的代號換成 `+N`；不另起一行。可關閉＝最後一行 `已完成`、worktree 沒有未 commit 的改動、遠端同名分支已有最新 commit（每次組狀態區都重查 git；omp 的 session 照同一套從回覆文字判）；第一次判成可關閉時事件紀錄多記一筆停下事件 `closable`。沒有目前這件、也沒在等時，分組那行就是第一行、右端只有 `0 面板`；什麼都沒有時不畫狀態區。
  - `~/.advisor/reports/weekly-<本週一>.md` 存在而 `weekly-<本週一>-proposals.json` 不存在時，最後多一行 `[每週改善] 報告：<路徑>`（只讀不寫這兩個檔）。
  - 狀態區不畫題目文字（批改單的題數也不畫）；要看題目按 `9`，或 `console.mjs detail`。輸入框空白時只有 `8`、`9`、`0` 是狀態區的鍵：`8` 把目前這件延後（等它回應時是先處理下一件）、`9` 用 `/focus-show` 印出目前這件、`0` 開面板並取得鍵盤（面板只從 `0` 開）；其他數字照常打進輸入框。任何子 session 停下或開始工作，下一次輪詢（5 秒內）狀態區就更新，不叫醒中控台。
- 面板分頁 `待回覆`(q)／`全部`(w)／`封存`(e)，內容是卡片。`全部` 列出所有沒封存的 session，閒置的也在裡面（卡片照樣標「閒置」），封存的只在 `封存`。`待回覆` 永遠跟狀態區同步：第一張是目前這件（不給數字）、其後照排隊順序標 1、2…（第 10 張是 0），面板開著時也即時重排；其他分頁依 repo 分組，數字照位置給 1–9、0。分頁列是 `q: 待回覆 N`、`w: 全部 N`、`e: 封存 N`，平均分散排滿整行：第一個分頁貼左、最後一個貼右，多出的空白平均分在分頁之間；下一行是整條細線、所選分頁正下方換成粗線 `━`，寬度等於該分頁標籤；不足 46 欄時沒選的分頁只留按鍵與數字，整行仍是一列。上／下在卡片間移動選取（兩端停住，移到畫面外的卡片會自動捲到完整可見）；左／右在面板裡引擎沒有綁鍵，切分頁用 q/w/e。按鍵說明 `qwe 切分頁 · 1-9,0/↑↓ 選卡片` 緊接在最後一張卡片（沒有卡片時是空白框）下面、中間空一行，補滿整行、文字置中，前後用灰色 `─` 夾住（兩邊至少各 2 個，太窄時先以「…」截說明文字），卡片少時下方留白；面板裡沒有統計。卡片多到要捲動時由 mod 自己管捲動（滾輪一張、翻頁鍵一整頁），按鍵說明跟著捲：沒捲到底時可見區域全部給卡片，捲到底時最後一張卡與按鍵說明都完整露出。數字鍵、Enter（焦點一律落在選取卡片的暱稱上）與點卡片上的暱稱都只選中卡片，不換狀態區上的題目、不印題目（有待審代回的卡按 Enter 照舊打開審核單）。按 `d` 在選中卡片正下方打開或收起摘要浮層（見下方〈浮層〉），浮層裡按 `p` 印出完整回報。卡片不畫外框：每張固定兩行，卡片上方空一行，一張佔 3 列；左側不畫直線，狀態色只上在狀態圖示；最左一格空白，接著兩格留給選中標記：選中的卡在這裡放強調色、粗體的 `✻`，其他卡留空，第二行也一起往右；三個分頁的卡片都一樣，repo 的分組標題線照舊貼左。面板拿到鍵盤且 `motion` 開著時，標記照 Claude Code 的轉圈字元 `· ✢ ✳ ✶ ✻ ✽` 來回轉（每 150ms 換一格）；鍵盤交回輸入框或 `motion: false` 時停在 `✻`，不為它開計時器。標題列是數字鍵、狀態圖示＋狀態字（💬 與等你的 ⏸ 都寫 `◆ 輪到你`）、暱稱（粗體、前景色；選中的用強調色），不畫題目、不放階段；有待審代回的卡狀態字寫 `◈ 待審核`（待回答的狀態色），標題列右端貼齊寫 `需審核 N 件`；建議好了的卡右端寫 `✓ 建議`（✓ 強調色）。代號太長時以「…」截短，標題列永遠一行。第二行在數字欄下方縮排，左邊是 branch（主題淡色）、右邊是 repo（主題淡色再加暗淡，右端貼齊卡片右緣），中間至少隔 2 格；放不下時 repo 至少留 8 格、branch 以「…」截短。卡片上不顯示選項（完整選項看橫條與印出的回報），也不顯示建議內容；面板裡任何地方（卡片、摘要浮層、審核單）都不顯示階段。`待回覆` 的卡片文字中只有暱稱是前景色粗體（選中時強調色粗體），狀態圖示與狀態字照原本的狀態色，branch、repo 都是灰字，`✓ 建議` 的 ✓ 照舊用強調色。卡片高度固定，捲動照每張 3 列計算；其他分頁的 repo 分組線上方空一行，與它下面第一張卡之間也空一行（就是每張卡上方那一行），捲動時一條分組線多算 2 列。卡片不放票名。「封存」分頁的卡片把暱稱按鈕換成「取消封存」：mod 直接跑 `console.mjs unarchive <代號>`，不經中控台、對話不留結果行，卡片照狀態回到其他分頁與看板。
- 面板開啟時要求 Claude Code 不畫面板本身的底色（`backgroundColor: "transparent"`），`neutral` 主題的面板背景就是終端機本身的背景；命名主題照舊畫自己的底色。
- 浮層：摘要畫在面板裡、不另開面板。浮層從選中卡片的正下方展開，蓋在下面的卡片上、不推動它們；卡片在面板下半部時改畫在卡片上方，但不蓋到分頁列。最上面一條強調色分隔線寫標題（`<代號> 摘要`），內容每行左側一條強調色粗線 `┃`，長內容照寬度換行、不截斷，最下面一條分隔線；摘要浮層在分隔線下面再一行灰字 `d 收起 · p 印出完整回報`。高度最多到面板可見範圍的邊緣；內容放不下時用滾輪、翻頁鍵或 `j`／`k` 捲動浮層內容，底線寫 `j/k 捲動 · 第 N–M 行／共 T 行`。浮層開著時滾輪與翻頁鍵只捲浮層、不捲卡片。再按一次 `d`、↑↓ 換到別張卡、切分頁、或按 Esc 把鍵盤交回輸入框，浮層就收起；同時只會有一個浮層。摘要浮層：直接從該 session 最新的摘要開始，不寫 repo、階段與票名。四層摘要一層一段：標籤（`在做什麼`、`卡在哪`、`做了什麼`、`▶ 要你決定`、`下一步`）是固定左欄、灰字，內容前景色，換行時對齊內容欄；`▶ 要你決定` 前空一行、整行強調色粗體；`下一步` 不加 ▶、照一般字色。舊摘要檔的舊標籤（前提、問題、解法、建議）照新標籤畫；沒有標籤的摘要照原文換行。沒有摘要時灰字寫 `還沒有摘要`，產生中灰字寫 `摘要產生中…`，舊摘要下方有新的在產生時多一行灰字 `新的摘要產生中…`。`p` 收起浮層後印出完整回報：經 `/focus-show` 印在中控台對話、不經模型，不換狀態區上的題目。`封存` 分頁的暱稱位置是取消封存按鈕，沒有摘要浮層。
- 只有緊急題上橫條：🔐 等待授權與 ⚠️ session 異常一停下就上；其他題先等 agent-skills advisor 在背景判完（預測的 `urgent` 欄），判成緊急才上橫條，判成非緊急就由中控台直接代回、不上橫條也不進待回覆；停下超過 2 分鐘還判不出來（還在判、預測失敗、舊版 advisor 沒判緊急）算緊急。緊急名單 10 類：等待授權、session 異常、不可逆或對外動作（推 main、force push、合併、刪資料或 branch、寫 Linear／Slack、改遠端設定）、代價高的決定（方向、範圍、資料寫入、權限）、需使用者本人判定的驗收與原型確認、加進〈不做〉或拿掉先前決定、要用秘密值、要連 SSH 或 RDS、連續 3 個假設失敗、判斷不出是否緊急；一則訊息只要有一題緊急，整則算緊急。沒有選項的開放題照同一套規則代回；一般句子的問句要在最後一段、不在程式碼、引用框、表格或標題裡才算在問，沒有問號的回覆不算。下面幾種也照常上橫條、不代回：問號不在最後一段的回覆、dev-flow 未定題（`第 N 題（gate#…）`，算第 5 類）、子 session 被攔截點擋下而停下的那則、define-goal 與前端精簡路徑的批改單（那張單就是這張票的實作前審核）、⏸ 回覆完畢。沒裝 advisor 時一律照舊上橫條。
- 代回（watcher 每一輪做）：非緊急題先用 `console.mjs review add` 的同一套格式記成審核項目（一則多題拆成多件，advisor 給每題一句題目、當前方案、影響範圍；有前例時寫出處），再用 advisor 的 `auto` 記成代回，最後用 `console.mjs reply --only <代號> -- <答案>` 送出（`--only` 只送這個代號，找不到就失敗，不退回送給橫條那題）。不倒數、不看題型猜中率。送失敗時替那幾件補一行「未送出」、用 advisor 的 `undo` 撤回，題目改上橫條。中控台輸入框有字時（mod 每次輪詢帶 `--typing 1`）這一輪不代回。前端完整路徑（第一則回覆寫「走完整」或 run folder 有 goal.md 且不是 `path: lean`）的批改單沒有 🔴 時代回「（中控台代回，待實作前審核）全照建議」，單上每個待決定各成一件審核項目、當前方案是它的建議；任何批改單有 🔴 都算緊急。前端 implement 停在「檢查完回「送審」」時，讀 run folder 的 `implement-report.md`：〈卡點與待裁決〉是「無」、沒有需人工判定的準則、那則也沒帶別的題目才自動送「送審」，否則照常上待回覆。
- 代回中：中控台代回後、子 session 還在跑這一輪時（`delegated.json` 裡這個 session 最近一筆代回，且這一輪的開始時間落在送出後 2 分鐘內），卡片狀態寫 `↻ 代回中`（已回覆色），第二行左邊改寫 `已代回：<答案>`；看板的狀態圖示換成 ↻、下一行寫 `代回中 · 已代回：<答案>`。它下次停下就恢復；`需審核 N 件` 照舊。
- 審核單：本輪有代回還沒送出審完的卡片狀態字寫 `待審核`、標題列右端寫 `需審核 N 件`（N 是本輪全部件數，已通過或改過、還沒送出審完的也算）。選中這張卡按 Enter（或點暱稱）在面板裡打開這個 worktree 的審核單（`console.mjs review data --json`），其他卡片暫時收起：第一行 `審核單：<代號>`，第二行左邊 branch（有 PR／MR 時接 ` · PR #N`）、右邊 repo；只分「先看：沒有前例」（每件四行：題目、當前方案、依據、影響範圍）與「照你過去的回答」（每件兩行：題目、當前方案＋出處）兩區，每區照編號由小到大排、件與件之間空一行，沒有開頭說明句；「當前方案」「依據」「影響範圍」等欄位名用主題最淡的灰；待審那件的題目用粗體，色碼主題用強調色混 60% 進前景色，neutral 維持前景色。↑↓ 選件；Enter 通過一件（縮成一行打勾、游標跳到下一件）；`e` 在那件下面就地打字改（標「已改」）；`x` 在那件下面就地問（按 `e`／`x` 後游標直接在輸入欄，打長了輸入欄照寬度換行、往下長高）：空白直接按 Enter＝要一個實際範例，打字＝問任何問題，回答插在那件下面（`問`／`答`，範例標 `範例`，答案裡的 Markdown 粗體標記不顯示），問很多輪時只展開最新一輪、前面幾輪收成一行，按 `h` 展開；`c` 把那件印到中控台對話討論，每打開一次審核單每件只送一次：第一次跳 `已送到中控台：第 N 件`，再按不再送出、只跳 `第 N 件已送去討論`，送出失敗才可再送，關掉審核單再開可再送一次；`o` 打開那件的範例檔；`a` 通過「照你過去的回答」那區剩下的件（「先看：沒有前例」那區不給 `a`，要一件一件按）；`u` 把這次最近通過或改的那件退回待審，連按逐件往回退；Esc 回卡片，進度存在紀錄裡。整張審完先停在「全部審完，按 Enter 送出審核結果」（這時還能按 `u`），按 Enter 才跑 `console.mjs review done`（還在跑的通過、改、退回會先等它跑完，退回後有待審的件就不送）；在這一行按 Esc、面板失去焦點或被關掉都不送，卡片仍標待審核，再打開時停在這一行等 Enter。
- 範例（`x` 空白 Enter，或 `console.mjs review ask --n N`）：前端畫面附子 session 記下的實際本機 dev server 改前改後截圖（`review add --before/--after`），截不到時附原型截圖並標「這是原型」（`--prototype`）；複雜邏輯附 mermaid 流程圖；簡單行為寫一個「如果…，會…」情境。範例檔放在審核紀錄旁的 `examples/`，按 `o` 打開。
