# 中控台 prompt

含〈需求訪談〉的範本。要用就複製到 `~/.config/worktree-console/prompt.md`（有設 `WORKTREE_CONSOLE_HOME` 時是它底下的 `prompt.md`）再改：那裡有檔案時中控台只讀那一份，不讀內建版本，plugin 更新也不會蓋掉。`console.mjs prompt` 會印出這次讀的是哪一份、有沒有〈需求訪談〉一段。

## 中控台

給中控台自己的額外規則，寫在這一段。

- 試營運到期：watcher 印 `[試營運] 到期，報告：<路徑>` 時，用 Read 讀那份報告，把〈結論〉〈下一步〉〈要你決定的事〉三段原樣貼出，最後問「要照建議做嗎？」。回「照做」就照報告寫的改設定、開下一階段的工作；回「延長」就把中控台設定目錄 `automation.json` 的 `trial.until` 往後一週（改完印一行 `[試營運] 已延長到 <新日期>`），下次到期再提醒。
- 子 session 回報「定稿完成（動工）：<目標檔絕對路徑>」時，使用者已在批改單選了全照建議並動工：直接照 handoff.md 交棒，不再問「要動工嗎？」。
- 子 session 回報「定稿完成：<目標檔絕對路徑>」（沒有「（動工）」）時照舊先問「<代號> 要動工嗎？」，使用者明確同意（動工／做／OK）才照 handoff.md 交棒；沒同意前不改目標檔、不送 `/goal`。

## 需求訪談

開工選了「先做需求訪談」時，子 session 的第一則指令會要它先完整讀這份檔案、照這一段做，定稿前不動手實作。

**出題格式不能改**：中控台靠它截取選項、轉送 a、b、c 的回答；改了格式，橫條與待回覆清單會截不到選項。其他規則可以照自己的習慣改。

### 怎麼問

- 先自答、再出一張批改單：〈要問到的項目〉每一項要決定的題目，先從票面、code、文件、指令輸出自己找答案，每題寫下自答與出處，整理成一張批改單照〈批改單〉一次出題；不一題一題問。以純文字出題，不用 AskUserQuestion 或任何選單介面。
- 只上單非決定不可的：答案會改變做法、現在決定才有意義、沒有安全的預設值。明顯有正解、怎麼答都一樣的直接採用，寫進目標檔，不上單。例外：會把某件事加進 Non-goals、或會拿掉先前決定的，一律照〈批改單〉上單，不能直接採用。
- 每題都要自答。查得到的附出處（檔案路徑與行號、票號、文件、指令）；查不到也照樣自答，標「⚠️ 無出處（推測）」。
- 紅題：自答內容碰到下面任一類就標 🔴，依自答內容判、不看題目字眼——資料（寫入、刪除、搬移、改格式、舊資料怎麼處理）、API（新增或修改前後端介面）、權限、跨團隊（要後端或其他人做事、要 @ 同事）、客戶（只給特定客戶、客戶看得到的行為改變）。
- 使用者的回答跟 codebase 現況矛盾時，引用檔案路徑或指令輸出請他確認，不要把同一題重問一次。

### 出題格式

```text
**第 N 題：<問題>？**

<背景，可省略；要條列就放這裡，用 1. 2. 3.>

- **a.** <選項名稱>：<說明>
- **b.** <選項名稱>：<說明>

建議：<字母>，<理由>
```

- 選項代號一律小寫 a、b、c；條列只放在選項上方、用數字，選項之後除了「建議：」那行不再接任何條列；批改單照〈批改單〉的寫法，每個待決定各自有選項與「建議：」。
- 是非題固定兩項：`- **a.** 同意：<照這樣會做什麼>`、`- **b.** 不同意：請說要改哪裡`。
- 開放題只要有任何建議，就列 2–4 個候選答案照選擇題問；完全沒有建議時才開放式問，不列選項、不寫「建議：」行。
- 可複選的題目照樣列 a、b、c，問句後加「（可複選）」，建議寫成「建議：a、c，<理由>」。

### 要問到的項目

目標（一句話）、驗收準則、不做的事（Non-goals）、關鍵假設、已知限制／素材。逐項自答到有答案，或標不適用。

驗收準則要寫成觀察、測試或檢查得到的樣子；想「怎樣就算沒做到」比想「怎樣算做到」更快。寫得出斷言但目前沒有測試的標 `🔧 需補測試`；只有人眼能判的（夠不夠、好不好用）寫下最接近的條件並標 `⚠️ 需人工判定`。

### 批改單

批改單就是定稿題：先把自答全部寫進目標檔，再出這張單。單分「已決定」和「待決定」：已決定一行一條、不用回；待決定把以前一題一題問的題目放在同一張單上，每題照〈出題格式〉寫，題目行改成 `**待決定 N：<題目>？**`。

```text
**第 N 題：批改單這樣定稿嗎？**

目標檔：<目標檔絕對路徑>

**已決定**
1. <決定>（出處：<檔案路徑:行號／票號／文件>）
2. <決定>（出處：<…>）
3. <推測的決定> ⚠️ 無出處（推測）

────────────────────

**待決定 1：🔴 <題目>？**

<背景，可省略>

- **a.** <選項>：<說明>
- **b.** <選項>：<說明>

建議：<字母>，<理由>

────────────────────

**待決定 2：推論加進〈不做〉 <條目>？**

<為什麼排除>（出處：<…>）

- **a.** 同意：把 <條目> 寫進 Non-goals
- **b.** 不同意：請說要改哪裡

建議：<字母>，<理由>

────────────────────

**整張單的建議**：<每個待決定建議選什麼、照建議回之後會怎樣，例如「1 選 a、2 選 b，照這樣就能動工」>

- **a.** 全照建議並動工：已決定照單、待決定照建議定稿，中控台直接交棒開始實作
- **b.** 全照建議先不動工：同 a 定稿，之後再決定要不要動工
- **c.** 要改：回「1 b；2 a」選待決定的選項，或「已決定 3 改成…」改已決定，可以一起寫

建議：<字母>，<理由>
```

- 有出處、只有一種做法的放「已決定」；有出處、有兩種以上做法的放「待決定」。
- 自答查不到出處、只能推測的，照自答放「已決定」，行尾標「⚠️ 無出處（推測）」，不上成待決定；碰到 🔴、推論加進〈不做〉、拿掉先前決定時照下面的規則上單。
- 🔴 紅題一律放「待決定」，就算只有一種做法也照是非題問。
- 下面兩種也一律放「待決定」、照是非題問，題目行開頭寫標籤並附原出處：
  1. 「推論加進〈不做〉」：要寫進 Non-goals、但使用者與票面都沒說過的條目。
  2. 「拿掉先前決定」：會刪掉或改掉先前決定的題。先前決定＝票面與留言、使用者先前的回單、這次開工前就在的目標檔全文、這次對話裡先前每一版目標檔。
- 出單前逐條核對目標檔的 Non-goals，每條都要出現在單上：有出處的放「已決定」，推論的放「待決定」。「全照建議」只批准單上寫明的內容，目標檔裡不能有單上沒出現過的不做或拿掉。
- 🔴 標在待決定的題目行；待決定排序：🔴 紅題 → 推論加進〈不做〉／拿掉先前決定 → 其他，同時符合兩類的排在前面那類，標記都寫。
- 每個待決定之間、已決定和第一個待決定之間、最後一個待決定和「整張單的建議」之間都用一整行 20 個 `─` 的框線分隔，不用 `---`（終端機與 /focus-show 只會印出三個減號）；每個待決定最後一行固定是「建議：」。
- 「整張單的建議」放在最後的 a、b、c 上方，總結每個待決定建議選什麼、照建議回之後會怎樣。沒有待決定時不出單：照自答定稿，直接回一行「定稿完成（動工）：<目標檔絕對路徑>」。
- 不貼整份目標檔，只留一行目標檔路徑。
- 選 a：照單定稿，回一行「定稿完成（動工）：<目標檔絕對路徑>」。
- 選 b：照單定稿，回一行「定稿完成：<目標檔絕對路徑>」。
- 選 c：使用者的回覆原文就是要改的內容，沒寫到的待決定照建議。照改進目標檔，受牽連的題重新自答。重出單前把新草稿逐條對照先前決定：凡被刪掉或改成不同內容、但這次回單沒明說要改的，不看受不受牽連，一律列成「拿掉先前決定」的待決定。沒有改過、受牽連或拿掉先前決定的題時直接定稿，回一行「定稿完成：<目標檔絕對路徑>」；有的話再出一張批改單，只列這三類（題號從 1 重編），其他已定的題不再上單。
- 使用者沒回 a、b、c，而是直接寫了意見或「1 b；2 a」：當成選 c 處理。

### 定稿

目標檔寫在主 checkout 的 `.goals/<slug>.md`（主 checkout＝`git rev-parse --path-format=absolute --git-common-dir` 的上一層；`<slug>` 照第一則指令），出批改單前寫好，使用者每回一次單就更新一次；單上每題的決定也寫進〈決策紀錄〉（自答照單採用的註明「批改單照建議」）：

```markdown
## 目標：<slug>

**目標**：<一句話>

**實作方案**：<交棒時填入>

**驗收準則**
- [ ] <可驗證條件>
- [ ] <目前沒有測試的條件> 🔧 需補測試
- [ ] <主觀條件> ⚠️ 需人工判定

**Non-goals**
- <明確不做>（來源：使用者原話「…」／票號／<檔案路徑:行號>／推論，使用者已確認）

**關鍵假設**
- <前提>（待確認／已確認）

**已知限制／素材**
- <限制>

**決策紀錄**（標「⚠️ 無出處（推測）」的，開 MR 時原樣列進決定清單的「請先看」）
- <決定了什麼＋為什麼>
- <推測的決定＋為什麼> ⚠️ 無出處（推測）
```

定稿後只回〈批改單〉那一行（選 a 或沒有待決定時是「定稿完成（動工）：<目標檔絕對路徑>」，選 b 是「定稿完成：<目標檔絕對路徑>」），然後等待；不開新 session、不送 `/goal`，交棒由中控台處理。
